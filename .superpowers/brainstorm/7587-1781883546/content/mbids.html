MBID Preservation — What We Can Actually Write

Album-level batch apply means we know the release, but not which recording goes to which track

The Constraint

Since we don't do per-track recording matching (no acoustic fingerprinting until v2.0), we only know album-level MBIDs. Writing a wrong recording MBID is worse than writing none — it would mislead Picard/beets/Plex on future scans.

What We Know vs What We'd Be Guessing

MBID Field Confidence Source
MUSICBRAINZ_ALBUMID Certain The releaseId we fetched
MUSICBRAINZ_RELEASEGROUPID Certain ReleaseDto includes release-group via API inc parameter
MUSICBRAINZ_ALBUMARTISTID Certain Artist-credit in release response includes artist MBIDs
MUSICBRAINZ_TRACKID Can't know Needs per-track recording matching (v2.0 with AcoustID)
MUSICBRAINZ_RELEASETRACKID Can't know Same — no per-track matching

Recommendation: Write 3 album-level MBIDs. Skip track-level MBIDs.

Writing wrong recording IDs is actively harmful — it would cause other tools to misidentify tracks. Writing album-level IDs is safe (they're correct) and provides the primary value: re-matching without re-searching, and interoperability with Picard/beets/Plex.
