Query Builder

// New helper in PlayerViewModel
fun buildAlbumSearchQuery(playlist: Playlist): AlbumSearchQuery {
  // Collect from ALL tracks, not just first
  val albumNames = playlist.trackList.mapNotNull { it.album }
  val albumArtists = playlist.trackList.mapNotNull {
    it.albumArtist?.takeIf { a -> a.isNotBlank() } ?: it.artist
  }
  
  // Mode (most common), not first
  val albumName = albumNames.groupingBy { it }.eachCount()
    .maxByOrNull { it.value }?.key ?: return@buildAlbumSearchQuery
  val consensusArtist = albumArtists.groupingBy { it }.eachCount()
    .maxByOrNull { it.value }?.key ?: ""
  
  // VA detection
  val isVA = isVariousArtists(consensusArtist)
  
  var query = "release:\"$albumName\""
  if (!isVA && consensusArtist.isNotBlank()) {
    query += " AND artist:\"$consensusArtist\""
  }
  return AlbumSearchQuery(query, consensusArtist, isVA)
}

Retry Logic

First search: query with artist (if not VA)

If results >= 3: return immediately

If results < 3 AND query had artist: retry without artist constraint

If results < 3 AND query already had no artist (VA): return whatever we got

Same 3-result threshold as existing recording search. Same pattern — one extra API call only on fallback.

VA Detection

fun isVariousArtists(artist: String): Boolean {
    val lowered = artist.lowercase().trim()
    return lowered == "various artists"
        || lowered == "various"
        || lowered == "va"
        || lowered == "v/a"
        || lowered == "various artist"
}

Covers the common representations. MusicBrainz uses the VA artist UUID internally, not the string — so omitting the artist clause entirely is the reliable path.
