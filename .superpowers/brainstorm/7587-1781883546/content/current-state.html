Album Metadata Fetch — Current vs Proposed Flow

7 gaps identified in the v1.8 implementation. Each one is a specific place in the pipeline.

Current Flow (Gaps Marked)

1 User long-presses album → "Fetch album info"
GAP 7: Uses first track's albumArtist/artist for search query
GAP 4: "Various Artists" doesn't match MB's VA format
2 searchReleases("release:Album AND artist:Artist")
3 User picks release from AlertDialog list
Dialog shows: title, artist, album, year — no format/country/track count to disambiguate variants
4 getReleaseMetadata(releaseId) → ReleaseMetadata
5 No changes preview — immediately batch-applies on selection
GAP 6: Blind apply. Desktop tools show diff before writing.
6 Per-track Metadata composed:
GAP 1: coverArtArchiveFront ignored — not wired to getCoverArtBytes
GAP 2: genres.firstOrNull() — drops all but first genre
GAP 3: No MBIDs written to tags (album, artist, recording, release-group)
7 Enqueued to _pendingMetadata Channel → MainActivity writes in background
GAP 5: Snackbar "success" fires on queue, not after write completion
