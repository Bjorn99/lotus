Phase 1 — Root Cause Investigation Results

Root Cause 1: Double-padding across tabs

The grid container adds horizontal padding, and then each content type adds its OWN padding too — with different amounts.

Tab Grid contentPadding Item padding Effective
Tracks 16dp 16dp (trackList) 32dp
Albums/Artists (rows) 16dp 8dp (playlistRows) 24dp
Albums/Artists (cards) 16dp 8dp (playlistCards) 24dp
Selection (tracks) 16dp 16dp (selectionList) 32dp
Selection (rows) 16dp 8dp (selectionRows) 24dp
Files: PlayerScreen.kt:1529 sets contentPadding = PaddingValues(horizontal = 16.dp) on the grid. TrackList.kt:54 adds .padding(horizontal = 16.dp) per track item. PlaylistRows.kt:75 adds .padding(8.dp) per row. PlaylistCards.kt:170 adds .padding(spaceBetween) (8dp default) per card.

Root Cause 2: Title letter jank — unconditional snapTo + style recomputation

A. snapTo launched every scroll frame:

// LazyGridWithCollapsibleTabsTopBar.kt:158 — NO guard on height change
coroutineScope.launch {
  topBarHeight.snapTo(newHeight) ← fires every frame, even when unchanged
}

// ColumnWithCollapsibleTopBar.kt:120 — HAS guard (added in v1.8 Task 5a)
if (newHeight != previousHeight) {
  coroutineScope.launch {
    topBarHeight.snapTo(newHeight)
  }
}

B. TextStyle recreated every frame: The collapseFraction fires on every animation frame, causing titleLarge.copy(fontSize = lerp(...)) to create a new TextStyle object each time. TabTitle then re-measures its IntrinsicSize.Min width on every recomposition.

C. Shared bounds animation: SharedTransitionLayout with rememberSharedContentState triggers bounds recalculation when the text changes between collapsed/expanded states. The AnimatedContent for showTabRow toggles cause the shared bounds to animate from one text position to another.

Root Cause 3: Landscape orientation bug

// LazyGridWithCollapsibleTabsTopBar.kt:127 — WRONG
LaunchedEffect(isInLandscapeOrientation) {
  topBarHeight.snapTo(maxTopBarHeight) ← takes MORE space in narrow landscape
}

// ColumnWithCollapsibleTopBar.kt:91 — CORRECT
LaunchedEffect(isInLandscapeOrientation) {
  if (isInLandscapeOrientation) {
    topBarHeight.snapTo(minTopBarHeight) ← conserves vertical space
  }
}

The LazyGrid variant takes MORE space in landscape. The Column variant takes less. This is likely the source of device-specific issues — landscape vs portrait behavior diverges.

Root Cause 4: No vertical padding on grid content

contentPadding = PaddingValues(horizontal = 16.dp) — no top/bottom padding. The first grid item starts at y=0, flush against the top bar boundary. On some devices the content appears cramped against the top bar, especially when the bar is collapsed to 60dp.

Bottom spacing is handled by a 200dp spacer item at the end of each grid — but this doesn't account for navigation bars or other system chrome.
