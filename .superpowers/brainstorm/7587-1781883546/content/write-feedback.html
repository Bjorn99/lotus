Gap 5 — Write Result Feedback

Current: snackbar shows "success" the moment tracks are queued to Channel. Actual writes haven't happened yet. Right now the _pendingMetadata Channel in MainActivity calls metadataWriter.writeMetadata() for each track and checks the result with checkMetadataWriteResult(). That check already handles success and failure — it just doesn't feed anything back to the ViewModel.

Two Approaches

A

Count writes, show single snackbar at end

The Channel fires N track writes. Track successes and failures in a counter. When all N complete, fire one snackbar: "Updated 10 of 12 tracks" (or "All 12 tracks updated successfully").

Pros

  • User gets accurate information
  • One snackbar, not 12
  • Surfaces partial failures

Cons

  • Snackbar delayed until last write finishes
  • New state to manage (write-in-progress counter)
B

Per-write snackbar from MainActivity

checkMetadataWriteResult already runs per track. Fire a snackbar there for each failure. Keep the immediate "success" on queue but add per-track error reporting for failures only.

Pros

  • Minimal code change
  • Keeps existing UX feel (immediate feedback)
  • Only surfaces errors, not noise

Cons

  • Success message still premature
  • Multiple snackbars if many failures
