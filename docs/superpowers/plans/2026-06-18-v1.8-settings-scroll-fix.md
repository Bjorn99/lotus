# Settings Scroll Jank Fix — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate dropped frames and sluggish scrolling across all settings sub-pages by fixing the `ColumnWithCollapsibleTopBar` scroll infrastructure — a `contentScrollState.value` subtraction bug, per-frame coroutine churn, and an unstable `SettingsItem` data class.

**Architecture:** The root cause is in `ColumnWithCollapsibleTopBar.kt`, the shared scroll wrapper used by all settings pages. Two bugs in `NestedScrollConnection.onPreScroll` create per-frame overhead and nonlinear scroll response. A third amplifying factor is `SettingsItem`'s unstable lambda-backed data class causing unnecessary recomposition. Fixes are surgical: align the Column variant's height calculation with the working LazyColumn variant, remove coroutine wrappers around synchronous `snapTo` calls, and stabilize the data class.

**Tech Stack:** Kotlin, Jetpack Compose, NestedScrollConnection, Animatable, MutableState

```kotlin
/**
 * Calculates the new top-bar height from a scroll delta.
 * The correct formula uses only the delta — NOT the absolute content scroll position.
 * The LazyColumn variant has always done this correctly; the Column variant
 * was incorrectly subtracting [contentScrollState.value] causing a positive-feedback
 * loop that made scroll feel sticky.
 */
internal fun calculateTopBarHeight(
    previousHeight: Float,
    scrollDelta: Float,
    minHeight: Float,
    maxHeight: Float
): Float {
    return (previousHeight + scrollDelta).coerceIn(minHeight, maxHeight)
}
```

```markdown
**5a. Settings scroll jank fix — ColumnWithCollapsibleTopBar**

**Problem:** All settings sub-pages feel sluggish during scrolling. Root cause: `ColumnWithCollapsibleTopBar.onPreScroll`
subtracts `contentScrollState.value` (absolute scroll position) from a delta-based height formula, creating a
positive-feedback loop where more scrolling produces faster-than-finger top-bar collapse. Additionally,
`coroutineScope.launch { snapTo() }` fires per scroll frame — ~120 coroutine allocations per second at 120fps.
`LaunchedEffect(topBarHeight.value)` cancels and relaunches its coroutine on every value change during collapse
animation. `SettingsItem` data class is unstable due to lambda-backed `onClick` field.

**Fix:**
- Replace `contentScrollState.value` subtraction with delta-only calculation (matching the LazyColumn variant)
- Guard `snapTo` with `newHeight != previousHeight` check, remove coroutine wrapper (snapTo is synchronous)
- Replace `LaunchedEffect(topBarHeight.value)` with `snapshotFlow` (avoids cancellation/relaunch churn)
- Annotate `SettingsItem` data class with `@Immutable`, extract `onClick` lambda as separate parameter
```
